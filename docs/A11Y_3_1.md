# Accessibility review — 3.1

_Reviewed 2026-10-22 on branch `arena/ebb1335f-babelish`._

## What was checked, and how

| Area | Method | Result |
|---|---|---|
| Tappable elements have an accessible name | Source scan of every `.tsx` (`tests/a11y.test.ts`) | Every `Pressable` has `accessibilityRole`/`Label`/`Hint`, or is an explicit decorative wrapper (`accessible={false}`) |
| Modals can be dismissed without the close button | Source scan | Every `Modal` has `onRequestClose` (Android back / Escape) |
| Tutor screen controls | Source assertions | Mic, send, stop and the conversation region are labelled; the picker is modal |
| Status changes are announced | Manual review + `accessibilityLiveRegion` | "… is thinking", voice errors and the daily-limit strip use polite live regions; the crash screen uses assertive |
| Progress semantics | Component review | `ProgressBar` exposes `role=progressbar` with min/max/now; `ProgressDots` is hidden from screen readers (decorative duplicate) |
| Touch targets | Manual review + `hitSlop` | Chips (~36 pt) and level chips gained hit slop to reach the 44 pt guideline; the composer buttons are 46 pt |

## What changed in this pass

- `Chip`: explicit `accessibilityLabel`, selected state, and expanded touch area.
- `Forgot password`: the back link is now a named button.
- `Speak`: the conversation list has a region label; the typing row, voice errors and
  the quota strip are live regions; the language picker is marked modal and its
  backdrop is a labelled close button; the level chips have hit slop.
- `ErrorBoundary`: the crash screen is `role=alert` with assertive announcements,
  and the detail line is redacted before display.

## Not verified here — needs a device or a browser screen reader

- VoiceOver (iOS) and TalkBack (Android) reading order, verbosity and focus traps.
- Dynamic type at 200 % / Android font scale: the chips and the composer have
  fixed heights, so clipping is plausible and must be checked by eye.
- Keyboard-only navigation on web (tab order, visible focus rings). react-native-web
  renders `Pressable` as a focusable element, but this was not exercised.
- Right-to-left layout: **not implemented** — tracked as P1 (interface i18n).
- Reduced-motion preferences: the only animation is the picker's fade, which is
  short and non-essential; no parallax or auto-playing motion exists.
- Colour contrast was fixed in 3.0.2 for the chat bubbles and chips, but the full
  palette has not been re-measured with a contrast tool in this pass.
